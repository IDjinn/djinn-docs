## Simple Enums

Enums define a set of named variants:

```djinn
enum Color {
    Red(),
    Green(),
    Blue()
}

i32 main() {
    Color c = Color::Red();
    return 0;
}
```

Variants are constructed with the `EnumName::Variant()` syntax.

## Variants with Payload

Variants can carry data (tagged unions / algebraic data types):

```djinn
enum Message {
    Empty(),
    Text(i8*),
    Number(i64),
    Pair(i32, i32)
}

i32 main() {
    Message m = Message::Number(42);
    return 0;
}
```

### Payload conversions

A payload converts like a function argument. A type that carries data is declared with `union`:

```djinn
union Shape {
    Circle(i32),
    Empty,
}

f64 half() {
    return 0.5;
}

i32 main() {
    Shape cast = Shape::Circle((i32)half());
    Shape narrowed = Shape::Circle(half()); // error E3054
    return 0;
}
```

- A wider type of the same kind converts implicitly. A narrowing or lossy conversion, a number given as a pointer, a pointer given as a number and a [pointer of another type](/docs/types#pointer-conversions) are error `E3054`.
- `null` or a nullable pointer given as `T*` is error `E3053`.
- A struct given as a number or pointer, or the reverse, is error `E3024`.
- A `str` or `string` given as an `i8*` payload, and a byte pointer given as a `str` or `string` payload, is converted.

The same rules apply to generic unions such as `optional::Value` and `result::Ok`. When the type arguments are inferred from the payloads, the first one fixes the type: with `union Pair<T> { Both(T, T), None, }` and `i64 wide`, `Pair::Both(1, wide)` is an error, while `Pair<i64>::Both(1, wide)` compiles.

## Generic Enums

Enums can be parameterized with generic types:

### optional{'<T>'}

```djinn
enum optional<T> {
    Empty(),
    Value(T)
}

i32 main() {
    optional<i32> some = optional<i32>::Value(42);
    optional<i32> none = optional<i32>::Empty();
    return 0;
}
```

### result{'<T, E>'}

```djinn
enum result<T, E> {
    Ok(T),
    Error(E)
}

i32 main() {
    result<i32, str> success = result<i32, str>::Ok(100);
    result<i32, str> failure = result<i32, str>::Error("not found");
    return 0;
}
```

Both `optional` and `result` are provided in the standard library via `import std::types`.

## Pattern Matching

Use `switch` as an expression to match enum variants and extract their payload. Each arm uses `->` to map a variant to a result value:

```djinn
enum optional<T> {
    Empty(),
    Value(T)
}

i32 main() {
    auto opt = optional<i32>::Value(69);

    i32 result = switch opt {
        Value val -> val,
        Empty -> -1
    };

    return result; // 69
}
```

### Variants without payload

For variants with no data, simply match the name:

```djinn
enum Color {
    Red(),
    Green(),
    Blue()
}

i32 main() {
    Color c = Color::Green();

    i32 result = switch c {
        Red -> 1,
        Green -> 2,
        Blue -> 3
    };

    return result; // 2
}
```

### Expressions in arms

Each arm can contain arbitrary expressions:

```djinn
auto opt = optional<i32>::Value(10);

i32 result = switch opt {
    Value val -> val * 2 + 1,
    Empty -> 0
};
// result == 21
```

### Pattern matching in functions

```djinn
i32 unwrap_or(optional<i32> opt, i32 default_val) {
    return switch opt {
        Value val -> val,
        Empty -> default_val
    };
}

i32 main() {
    auto a = optional<i32>::Value(50);
    auto b = optional<i32>::Empty();

    return unwrap_or(a, 0) + unwrap_or(b, 99); // 149
}
```

### Multi-payload matching

Generic enums with multiple type parameters work the same way:

```djinn
enum result<T, E> {
    Ok(T),
    Error(E)
}

i32 main() {
    auto r = result<i32, i32>::Error(7);

    i32 val = switch r {
        Ok v -> v,
        Error e -> e
    };

    return val; // 7
}
```
