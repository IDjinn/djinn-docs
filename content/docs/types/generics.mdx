## Generic Structs

Structs can be parameterized with one or more type parameters:

```djinn
struct Box<T> {
    T value;

    Box(T v) {
        this.value = v;
    }

    public T get() {
        return this.value;
    }
}

i32 main() {
    Box<i32> b = Box<i32>(42);
    return b.get();  // 42
}
```

### Multiple Type Parameters

```djinn
struct Pair<K, V> {
    K key;
    V value;
}

i32 main() {
    Pair<i32, i32> p = { .key = 42, .value = 100 };
    return p.key + p.value;  // 142
}
```

## Monomorphization

Generics are monomorphized at compile time. Each unique instantiation (e.g., `Box<i32>`, `Box<i64>`) generates a separate struct and method set. There is no runtime cost.

## Generic Enums

Enums also support generics:

```djinn
enum optional<T> {
    Empty(),
    Value(T)
}

optional<i32> x = optional<i32>::Value(42);
```

See [Enums](/docs/types/enums) for more details.

## Generic Constraints

Type parameters can be constrained with interfaces using `where`:

```djinn
interface IValue {
    i32 getValue();
}

struct Container<T> where T : IValue {
    T item;
}
```

Only types that implement `IValue` can be used as `T`. Types that don't satisfy the constraint produce a compile error:

```djinn
struct MyItem : IValue {
    i32 data;
    i32 getValue() { return this.data; }
}

struct Plain { i32 x; }

Container<MyItem> ok = { .item = { .data = 42 } };   // ok
Container<Plain> err = { .item = { .x = 1 } };        // error: Plain does not implement IValue
```

### Multiple Constraints

A type parameter can require multiple interfaces:

```djinn
interface IReadable {
    i32 read();
}

interface IWritable {
    void write(i32 val);
}

struct Store<T> where T : IReadable, IWritable {
    T backend;
}
```

`T` must implement both `IReadable` and `IWritable`. Implementing only one produces a compile error.

### Constraints on Multiple Parameters

Use separate `where` clauses joined by `;`:

```djinn
interface IHashable {
    i32 hash();
}

interface ISerializable {
    i32 serialize();
}

struct Map<K, V> where K : IHashable; where V : ISerializable {
    K key;
    V value;
}
```

### Constraints on Enums

`where` clauses work on enums too:

```djinn
interface IValue {
    i32 getValue();
}

enum Wrapper<T> where T : IValue {
    Some(T),
    None()
}
```

### Constraints on Interfaces

Generic interfaces can constrain their own type parameters:

```djinn
interface IEquatable {
    i32 equals();
}

interface ISortable<T> where T : IEquatable {
    void sort();
}
```

### Constraints with Implements

A struct can have both a `where` clause on its generic parameters and implement interfaces:

```djinn
interface IContainer {
    i32 size();
}

interface IValue {
    i32 getValue();
}

struct TypedBox<T> where T : IValue : IContainer {
    T item;
    i32 count;

    i32 size() { return this.count; }
}
```

## Checking at the Definition

The body of a generic struct, `impl` block, function or method is checked where it is declared, even when nothing instantiates it.

A member missing from a type that does not depend on the parameters is an error (`E3017` for a field, `E3027` for a method):

```djinn
struct Inner {
    i32 value;
}

struct Outer<T> {
    Inner inner;
    T item;

    void broken() {
        this.inner.nope();   // E3027: Inner has no 'nope'
    }
}
```

On a parameter with `where` bounds, a member that neither the bounds nor any type implementing all of them has is `E3074`:

```djinn
interface Named {
    i32 name_length();
}

i32 touch<T>(T value) where T : Named {
    return value.size;       // E3074: no type implementing Named has 'size'
}
```

A type implements a bound when it declares the interface or has a member of every name the interface requires. If one such type has the member, the body is accepted and each instance is checked with its own argument.

A parameter without bounds accepts any member until the instance is checked.

### In Libraries

Building a library checks the generic bodies it declares: with such an error no `.djlib` is written. A program that uses the library does not check those bodies again at their declaration, only the instances it makes. The `where` bounds are kept in the library and apply to the type arguments of the program.

## Nested Generics

Generic types can be nested as type arguments:

```djinn
struct Pair<K, V> {
    K key;
    V value;
}

struct Wrapper<T> {
    T data;
    i32 id;
}

i32 main() {
    Wrapper<Pair<i32, i32>> w;
    return 0;
}
```

## Generic Return Types

Functions can return generic structs:

```djinn
struct Pair<K, V> {
    K key;
    V value;
}

Pair<i32, i32> makePair(i32 k, i32 v) {
    return { .key = k, .value = v };
}

i32 main() {
    auto p = makePair(5, 10);
    return p.key + p.value;  // 15
}
```

## Constant Parameters

A template parameter can stand for a constant, as non-type template parameters do in C++. An untyped parameter takes a
type or a constant; a typed one (`i32 N`, `bool ON`, `Color C`) takes only a constant of that type.

```djinn
struct Array<T, N> {
    T[N] data;          // an inline array: N values held in the struct itself
}

struct Ring<T, u8 CAPACITY> {
    T[CAPACITY] items;
    mut i32 count;
}

i32 main() {
    Array<i32, 5> numbers = {};
    Ring<f64, 8> recent = {};
    return 0;
}
```

A constant argument is a literal, a `constexpr` global, a struct constant or enum variant (`Flag<Color::Red>`), or a
parenthesized constant expression, which may call `constexpr` functions. In a call to a generic function a plain constant
name goes after a type argument (`count<i32, LANES>()`) or in parentheses (`shade<(LANES)>()`), since `a < b` alone is a
comparison:

```djinn
constexpr i64 cells(i64 n) {
    return n * n;
}

struct Matrix<i32 N> {
    i32[(cells(N))] data;   // Matrix<5> holds 25 values
    i32[(N * 2)] edges;
}
```

Inside an instance the parameter is its constant: it folds like a literal (`for (mut i32 i = 0; i < N; ...)`), sizes
arrays and is passed on to other templates (`Holder<T, (N + 1)>`). Using it as a type is an error (E3079), so is giving
a type to a typed parameter (E3080) or a value that does not fit it (E3078). The constant is inferred from the arguments
of a generic function like a type is:

```djinn
i64 total<T, i32 N>(Array<T, N>* values) {
    return N;
}
```

`Name<args>.member(...)` calls a static member of an instance: `Array<i32, 4>.filled(0)`. A template that
instantiates itself without end stops at 256 levels (E3084).

### Inline arrays

`T[N]` is an array held inside the value (a field, a local, a template argument), copied with it. It is built with `{}`
(all zeros) or an array literal of exactly N values. Indexing is checked: a constant index outside the array is a
compile error (E3057) and any other index is checked at run time (R10010, which the optimizer drops once the index is
proven). An element can only be changed through a `mut` holder, and the elements must be trivially copyable (E3081 for
`string[4]`: use `arr<T>` or a `List` for values that own memory). Because it is copied as a whole, one type holds at
most 4096 values in inline arrays (E3081): larger buffers also belong in `arr<T>` or `List<T>`.

## Type Questions

`if constexpr` checks only the branch it takes, so generic code can have one branch per kind of type. `std::types`
answers the questions at compile time:

```djinn
import std::types;

i32 describe<T>(T value) {
    if constexpr is_integer<T>() {
        return 1;
    } else if constexpr is_float<T>() {
        return 2;
    } else {
        return 3;
    }
}
```

The functions are `is_integer`, `is_signed`, `is_unsigned`, `is_float`, `is_number`, `is_bool`, `is_char`, `is_pointer`,
`is_enum`, `is_struct`, `is_array`, `is_copyable` and `is_same<A, B>`; they wrap the intrinsics `type_trait(T, name)` and
`same_type(A, B)`.

Variadic templates (`Tuple<Types...>`) are not supported yet.
